# check.md · 렌더 뒤 점검 기준 (critic이 쓴다)

> critic은 **판정만 한다.** 고치지 않는다. 불통과는 번호 목록으로 `out/<영상이름>/gates.md`에 적는다(몇 초 · 무엇이 · 고칠 방향).
> 1주차 원본: 1주차 프로젝트 `docs/motion.md` 0-4 · 6절. 값마다 출처를 적었다. 출처 적는 법은 `docs/sound.md`와 같다.
> 소리와 1배속 시청은 선생님이 직접 한다. critic은 "들어 봤다"고 적지 않는다.

## 1. 명령 (`scripts/check-render.sh <영상.mp4>`가 세 가지를 한꺼번에 돌린다)
| 점검 | FFmpeg 필터 | 출처 |
|---|---|---|
| 화면 정지 | `freezedetect=n=-80dB:d=3` (3초 이상 화면이 그대로인 구간) | 1주차 motion.md 6절 |
| 무음 | `silencedetect=noise=-40dB:d=1.5` (1.5초 이상 소리가 없는 구간) | 1주차 motion.md 6절 |
| 음량 | `loudnorm=I=-16:TP=-1.5:LRA=11`로 맞춘 뒤 다시 재기(`print_format=json`) | 1주차 motion.md 4절 |
| 밝기 | `signalstats`의 평균 밝기(YAVG) | `docs/video.md` 2장(70% 이상 = 179) |

- 영상 끝까지 이어지는 정지 · 무음은 `start`만 나온다. **영상 길이에서 `start`를 빼서** 길이를 계산한다. — 1주차 motion.md 6절

## 2. 불통과 판정
**정지와 무음은 아래 세 곳이 아닌 곳에서 나오면 불통과**로 `gates.md`에 적는다. — 선생님 지시(11/9) · 1주차 motion.md 0-2 · 0-4

| 허용되는 곳 | 어떤 곳인가 | 출처 |
|---|---|---|
| **읽을 시간** | 글 · 표 · 숫자를 처음 보여 주는 때(내레이션 뒤 3초 안), "기억해요" 줄마다 3초 안팎 | 1주차 motion.md 0-4 · `docs/motion.md` 4-3 |
| **생각할 시간** | 학생이 답을 고르는 질문의 카운트다운(숫자 1초 간격) | 1주차 motion.md 0-2 · `docs/motion.md` 4-1 |
| **마지막 2초** | 내레이션이 끝난 뒤 마지막 화면을 그대로 두는 2초 안팎 | 1주차 motion.md 0-4 |

- 세 곳이 장면표 어디인지는 `03-scenes.md`의 "머무는 종류" 칸으로 가린다. 칸이 비어 있으면 일반 장면으로 본다.
- **허용되는 곳 안의 길이 한계** (이 한계를 넘으면 불통과). 정지와 무음 모두 같은 표로 본다:

| 허용되는 곳 | 정지 한계 | 무음 한계 | 출처 |
|---|---|---|---|
| 읽을 시간 | **3.5초** | **3.5초** | 1주차 0-4의 "3초 안(안팎)"에 0.5초 여유를 더한 **정한 값**. `freezedetect d=3`은 3초 미만을 못 잡으니 3.0~3.5초는 통과, 3.5초 초과는 불통과 |
| 생각할 시간 | 카운트다운 전체 길이 | 카운트다운 전체 길이 | 1주차 0-2(숫자 1초 간격, 질문 문장 동안 화면은 4초 넘게 멈추지 않음) |
| 마지막 2초 | 2.0초 ± 0.5초 | 2.0초 ± 0.5초 | 1주차 0-4 "2초 그대로"에 ±0.5초 여유를 더한 **정한 값**(1주차 6절에는 "2초 안팎"만 있음) |

- **허용되는 곳 밖**에서는 3초 이상 정지, 1.5초 이상 무음이 나오면 불통과. 장면 사이 내레이션 없는 쉼은 1.5초 이하. — 1주차 0-4
- 무음 길이가 정확히 **1.50초**면 `silencedetect d=1.5` 경계에 걸려 잡힌다. 그 구간이 장면표 "읽을 시간"(예: 표를 읽어 준 뒤 0.9초 머묾 + 나가기 0.6초)이면 허용 구간으로 판정한다. 읽을 시간이 아닌 곳이면 불통과. — 11/9 pilot-slide14
- **읽을 시간에는 내레이션이 쉬어도 된다**(글 · 표 · 숫자를 읽는 시간). 1주차 0-4의 "쉼 1.5초 이하"는 읽을 시간 · 생각할 시간 밖의 장면 사이 쉼에만 적용한다. — 선생님 지시(11/9). 1주차 1편 영상에도 읽을 시간에 1.5초 넘는 무음이 있었다(2.0~2.6초)
- **바탕 떨림(보일)은 영상에 쓰지 않는다**(`docs/motion.md` 1-1 `dur-boil` 꺼 둠). 바탕이 계속 움직이면 `freezedetect`가 정지를 못 잡아 이 장의 정지 판정이 무력해진다. 켜려면 선생님 결정 + 정지 검사 방식을 바꿔야 한다. — 정한 값(11/9 점검)

## 4. `gates.md` 쓰는 모양
```
# gates.md · <영상이름> · <날짜>
판정: 통과 / 불통과 (n건)
## 불통과
1. 12.4~16.9초 · 화면이 4.5초 그대로 (읽을 시간 아님) · 장면4에 변화 한 가지 더하기
2. ...
## 통과한 것
- 음량 I −16.2 LUFS · TP −1.7 dBTP
## 선생님이 직접 볼 것
- 소리(효과음 · 읽기) · 1배속 시청
```
- 판정이 "통과"여도 "선생님이 직접 볼 것"은 남긴다.
- 불통과를 고치는 것은 builder이다. critic이 고친 뒤 다시 판정하지 않는다.

## 5. 렌더에서만 생기는 문제 (11/9 시험 영상 pilot-slide14에서 알게 됨 · 다음에도 쓸 기본값)
- **시작 전 숨김은 CSS 초기 `opacity:0` + 타임라인 `tl.set(요소, {opacity:1}, 시각)`으로 만든다.** `tl.fromTo(요소, {opacity:0}, {opacity:1, duration:0, ease:"steps(1)"}, 시각)` 같은 "길이 0 fromTo"로 숨기지 않는다. 미리보기 스냅샷에서는 숨겨지는데 **렌더(mp4)에서는 숨겨지지 않아서**, 표 머리줄 · 줄 · 출처 · 화살촉이 카드가 열리는 7.9초부터 다 보이고 화면이 8.33~21.60초(13.27초) 그대로였다(critic 렌더 뒤 판정 불통과). 글자 한 글자씩 찍기(`.ch`)는 처음부터 이 방식이라 렌더에서도 맞았다. — 11/9 pilot-slide14 gates.md
- **스냅보드(미리보기) 승인만으로는 이 문제를 못 잡는다.** builder 는 렌더한 mp4 에서 "나오기 전 · 나온 뒤" 프레임을 `ffmpeg -ss`로 뽑아(예: 표가 나오기 전 7.9 · 8.5초, 나온 뒤 12.5 · 20.0초) 숨김이 시각대로 풀리는지 눈으로 확인한 뒤 critic 에 넘긴다.
- critic 은 렌더 뒤 판정에서 정지 구간이 읽을 시간 밖에서 길게 나오면 **원인이 "숨겨야 할 것이 먼저 보임"인지** 장면 파일과 캡처로 가려 적는다.
